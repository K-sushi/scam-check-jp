# 次の版 (v2) の設計 — 2026-11-06 案

## なぜ作り直すか
初版は、公的機関が引用した詐欺の文 60 件のうち 14 件 (23%) しか指摘できなかった ([eval/results_primary.json](../eval/results_primary.json))。
見逃しは3つの型に分かれる。

| 型 | 例 | 原因 | v2 の対策 |
|:--|:--|:--|:--|
| 理由をつけてお金を求める | 「保釈金がいる」「旅費を送って」 | 「お金を送れ」を見る規則が無い | **お金の要求の規則**を足す |
| ロマンス詐欺の最初の段階 | 「愛してる」「日本の友達が欲しい」 | 文だけでは普通の会話と区別できない | **状況の質問**で判定する |
| 言い回しのずれ | 「出金には手数料が必要だ」 | 語尾まで固定して照合していた | 語尾を照合に含めない |

警察・自治体のチェックリストは、言葉ではなく**状況**で書かれている。
例: 「まだ会ったことのない異性から金銭の話が出たら詐欺を疑う」(兵庫県)。v2 はこれを判定の中心にする。

## 画面の流れ
1. **質問 (必須、4 問、はい / いいえ / わからない の大きなボタン)**
   - Q1 相手と、実際に会ったことがありますか?
   - Q2 相手から、お金を払う・送る・貸す・投資するように言われましたか?
   - Q3 相手と知り合ったのは、SNS・ネット広告・マッチングアプリ・突然の連絡ですか?
   - Q4 「利益や荷物を受け取るには、先に手数料・税金・保証金が要る」と言われましたか?
2. **メッセージ (任意)**: 貼れば、初版と同じく文の特徴も表示する。
3. **結果**: 状況の判定と文の判定のうち、**重い方**を表示する。どの結果でも #9110 へ案内する (初版と同じ)。

## 状況の判定 (固定の規則)
| 条件 | 結果 | 根拠 |
|:--|:--|:--|
| Q4 が「はい」 | 詐欺の可能性が高い | 警察庁「全額引き出しのための手数料などを要求する」 |
| Q1 が「いいえ」かつ Q2 が「はい」 | 詐欺の可能性が高い | 兵庫県「会ったことのない異性から金銭の話」 |
| Q3 が「はい」かつ Q2 が「はい」 | 詐欺の可能性が高い | 警察庁「SNS の DM で投資話を持ちかけられた」 |
| Q2 が「はい」(上以外) | 注意 | — |
| Q1 が「いいえ」かつ Q3 が「はい」 | 注意 (お金の話が出たら、すぐ相談を) | ロマンス詐欺の初期段階 |
| それ以外 | 当たらなかった (「安全」とは言わない) | — |

「わからない」は「はい」と同じに扱う (見逃しより、念のための相談の方が害が小さいため)。

## 文の規則の変更
- **追加**: お金の要求。「送って / 払って / 振り込んで / 貸して / 立て替えて / いる / 必要」と、
  名目 (保釈金・関税・旅費・配送料・治療費・手術・調査費用・手数料・税金・保証金 など) が同じ文に並ぶもの。
- **変更**: 語尾 (「です」「だ」「となります」など) を照合の条件から外す。
- 初版の規則は残す。初版で直した誤検出 4 文は、新しいテストファイルで回帰テストにする (初版のテストファイルは書き換えない)。

## 測り方 (v2 用の事前登録の骨子。実装の前に別ファイルで凍結する)
- **データは新しく集める。** 初版の評価データとその出典ページ、規則の出典ページは全部除外する。
  集めるのは、初版と同じく規則を見ない別の担当。
- 状況の質問を測るために、データは「文」ではなく**事例**の単位にする。
  公的機関の事例の説明 (「SNS で知り合った男性から…」) から、担当が Q1〜Q4 の答えと、引用された文を取り出す。
  説明に書かれていない質問は「わからない」にする。
- 詐欺でない側は、正規の状況の事例 (証券口座の開設、銀行の窓口での投資の相談、知人との割り勘など) を、
  公的機関・正規業者の説明から取り出す。**ここは作り話になりやすいので、出典の文から読み取れる答えだけを使う。**
- 主指標と合格の線 (案):

| 指標 | 合格の線 |
|:--|:--|
| 事例の検出率 (状況 + 文、`no-match` 以外) | 0.80 以上 |
| 正規の事例を「可能性が高い」と誤判定する率 | 0.05 以下 |
| 参考: 文だけの検出率 | 線なし (初版の 23% と比べる) |

## 弱点 (先に書いておく)
- 利用者が質問に正直に答えるとは限らない。特に、相手を信じ切っている人は Q2 に「いいえ」と答えうる。
- 事例から質問の答えを読み取る作業に、担当の解釈が入る。答えの根拠となる原文を、事例ごとに記録させる。
- 正規の事例は集めにくく、件数が少なくなりうる (30 件未満なら合否を出さない)。

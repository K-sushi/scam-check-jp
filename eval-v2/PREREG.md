# v2 の検出率の測定 — 事前登録 (2026-11-06)

設計: [docs/DESIGN-v2.md](../docs/DESIGN-v2.md)。このファイルと `eval-v2/score.mjs` を、v2 の規則の実装とデータの収集の**前に** commit する。以後、結果を見てから変えない。

## 対象
- `rules.mjs` が export する `assess({ answers, text })`。
  - `answers`: `{ q1, q2, q3, q4 }`、各値は `"yes"` / `"no"` / `"unknown"`。
  - 戻り値の `verdict`: `"high"` / `"caution"` / `"no-match"` (状況の判定と文の判定のうち重い方)。
- 採点するのは、v2 の規則を凍結した commit (採点の直前に commit し、その id を結果に書く)。

## データ
- **規則を見ない別の担当**が、新しく集める。担当には `rules.mjs` もこのリポジトリも見せない。
- 単位は**事例**。公的機関 (警察・自治体・消費者庁・国民生活センター・金融庁など) が説明した 1 件の被害や手口が 1 事例。
- 各事例に、Q1〜Q4 の答えと、その答えの根拠になった原文、事例に引用されたメッセージ (あれば) を付ける。説明に書かれていない質問は `"unknown"`。
- 正規の事例 (`label: benign`): 公的機関・正規の業者の説明から読み取れる、正規のお金の場面 (証券口座の開設、窓口での投資の相談、正規業者からのお知らせなど)。
- **除外する出典**: 初版の評価データの出典ページ全部、規則の出典ページ (警察庁 SOS47 の投資詐欺ページ、茨城県警察、兵庫県の注意喚起)。
- 目標: 各 40 件以上、60 件で打ち切り。60 件を超えたら id 順の先頭 60 件を主の判定に使い、全件は参考にする (初版と同じ)。

## 指標
| 指標 | 定義 | 合格の線 |
|:--|:--|:--|
| **事例の検出率** (主) | 詐欺の事例のうち `assess` の `verdict != no-match` の割合 | 0.80 以上 |
| **強い誤判定率** (主) | 正規の事例のうち `verdict == high` の割合 | 0.05 以下 |
| 文だけの検出率 (参考) | メッセージがある詐欺の事例について、`answers` を全部 `"no"` にした時の `verdict != no-match` の割合 | 線なし |
| 質問が全部 `unknown` の事例の割合 (参考) | — | 線なし |

- 合否は点推定、Wilson の 95% 信頼区間を併記する。
- どちらかが 30 件未満なら合否を出さず「件数不足」。

## 注意して読むべき点 (先に書く)
- 「わからない」を「はい」と同じに扱う設計なので、説明の少ない事例ほど検出されやすい。
  質問が全部 `unknown` の事例の割合を参考指標で出し、検出率がそれに支えられていないかを見る。
- 同じ理由で、正規の事例でも `unknown` が多いと誤判定が増える。これも主指標にそのまま出る。
